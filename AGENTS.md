# AGENTS.md

This document orients developers and AI agents working on this codebase.

## Project Overview

FinWise AI — a personal finance advisor. Someone enters their income,
expenses, and a savings goal; the app returns a budget breakdown, saving
suggestions, a monthly summary, a what-if simulator, and a chat interface.
Built with TanStack Start and deployed on Netlify.

See `README.md` for what's implemented and how to run it, and `PLAN.md` for
the roadmap (a real Gemini-backed function, persistence beyond
`localStorage`).

### Tech Stack

| Layer | Technology |
|-------|------------|
| Framework | TanStack Start |
| Frontend | React 19, TanStack Router v1 (file-based routing) |
| Build | Vite 7 |
| Styling | Tailwind CSS 4 |
| Charts | Chart.js + react-chartjs-2 |
| Icons | lucide-react |
| Language | TypeScript 5.9 (strict mode) |
| Deployment | Netlify |

There is no backend yet — no database, no server functions, no external API
calls. Everything in `src/` runs client-side (with TanStack Start SSR for the
initial HTML shell only). `PLAN.md` covers adding a Netlify Function for real
Gemini calls and moving plan storage server-side.

## Key Concepts

### File-Based Routing (TanStack Router)

Route files use flat dot-notation: `dashboard.budget.tsx` is nested under
`dashboard.tsx` and serves `/dashboard/budget`. `dashboard.index.tsx` serves
the exact `/dashboard` path. Every route file exports `Route` via
`createFileRoute(path)({ component })`.

### Plan state (`FinancialPlanProvider`)

The user's financial plan lives in React Context, backed by `localStorage`
(key `finwise:plan`). The context exposes `plan`, `ready`, `setPlan`, and
`clearPlan`. `ready` flips to `true` only after the client-side hydration
effect runs — routes that depend on `plan` should treat `ready === false` as
"still loading," not "no plan," to avoid a flash of the empty state during
SSR/hydration. `dashboard.tsx` implements this gate once for every dashboard
tab.

### The "AI" layer (`src/lib/aiFixtures.ts`)

Saving suggestions, the monthly summary, and chat replies are generated by
deterministic rules over the real budget numbers (from `src/lib/budget.ts`),
not by a live model call. This keeps the product fully functional and
demoable with zero setup. `PLAN.md` describes replacing this module's outputs
with a Netlify Function that calls Gemini, without changing any component
that consumes it — the function signatures (`generateSavingSuggestions`,
`generateMonthlySummary`, `generateChatResponse`) are the seam to swap.

### Demo Mode

`src/lib/demoData.ts` exports `DEMO_PLAN`, a fixed sample plan. "Try Demo"
buttons call `setPlan(DEMO_PLAN)` and navigate to `/dashboard` — no network
call, so it always works.

## Conventions

### Naming
- Components: PascalCase
- Utilities/hooks: camelCase
- Routes: dot-separated flat files matching the URL path

### Styling
- Tailwind CSS utility classes only, no separate CSS files per component
- Indigo/blue as the primary accent, white/light-gray surfaces, rounded-2xl
  cards with subtle shadows (see any file in `src/components/dashboard/` for
  the pattern)

### TypeScript
- Strict mode enabled
- Import paths use the `@/` alias
- Prefer explicit literal union types over broad `keyof` types for anything
  used in indexed access — avoids type widening surprises
- Type-only imports use the `type` keyword

### Charts
- `src/lib/chartSetup.ts` must be imported (for its side effect) before any
  chart component renders — `dashboard.tsx` already does this once for the
  whole dashboard subtree
- Palette: needs/blue `#2a78d6`, wants/orange `#eb6834`, savings/green
  `#1baf7a` — chosen from a validated colorblind-safe categorical set; reuse
  these hex values rather than introducing new series colors
